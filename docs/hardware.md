# Hardware and firmware

## Components

- ESP32 development board (classic ESP32 with ADC1 on GPIO34).
- MQ-5 gas sensor module.
- Three LEDs: green, yellow, red.
- Suitable series resistors for the LEDs.
- A stable supply for the MQ-5 heater, as required by the module.

There is **no buzzer** in this project. The firmware has no buzzer pin, tone
call or alarm sound.

## Pin assignment

| Function | ESP32 pin | Firmware constant | Direction | Behaviour |
|---|---|---|---|---|
| MQ-5 analog output | **GPIO34** | `MQ5_PIN` | input | 12-bit ADC, `ADC_11db` attenuation |
| Green LED | **GPIO25** | `GREEN_LED` | output | HIGH for `Normal` |
| Yellow LED | **GPIO26** | `YELLOW_LED` | output | HIGH for `Warning` |
| Red LED | **GPIO27** | `RED_LED` | output | HIGH for `Danger` |

GPIO34 is an input-only pin on the classic ESP32 and is ADC1 channel 6. It has
no internal pull-up or pull-down. The sketch sets the ADC resolution to 12 bits
and the attenuation to `ADC_11db`, giving an approximate 0–3.3 V input range.

```text
MQ-5 AO  ──────────────► GPIO34
MQ-5 VCC ──────────────► module supply (commonly 5 V; check the module)
MQ-5 GND ──────────────► GND
GPIO25   ── resistor ──► green LED  ──► GND
GPIO26   ── resistor ──► yellow LED ──► GND
GPIO27   ── resistor ──► red LED    ──► GND
```

All grounds must be common. The sketch does not define the MQ-5 supply wiring:
some modules accept 5 V, some accept 3.3 V, and the analog output scaling
depends on the board. **Never apply more than 3.3 V to GPIO34.** If the module's
analog output can exceed 3.3 V, use a suitable divider or level shifter.

## ADC configuration

```cpp
analogReadResolution(12);
analogSetPinAttenuation(MQ5_PIN, ADC_11db);
```

- Resolution: 12 bits, raw values 0..4095.
- Attenuation: `ADC_11db` (approximately 0–3.3 V on the classic ESP32).
- Sample period: 1000 ms.
- The model was trained on raw ADC counts in 0..4095; it does not use voltage
  conversion or temperature/humidity compensation.

The ESP32 ADC is not a precision instrument. Its readings vary with supply,
temperature and the source impedance of the sensor module. Real deployment would
require calibration against a reference and an assessment of the MQ-5 warm-up
behaviour.

## LED behaviour

The firmware first turns all three LEDs off, then turns on exactly one LED based
on the model's argmax class:

| Class | Green GPIO25 | Yellow GPIO26 | Red GPIO27 |
|---|---|---|---|
| `Normal` | ON | off | off |
| `Warning` | off | ON | off |
| `Danger` | off | off | ON |
| Unexpected class | off | off | off |

The LEDs are active HIGH: `digitalWrite(pin, HIGH)` turns the LED on when the
LED is wired from the pin through a resistor to ground.

## Serial protocol

- Baud rate: **115200**
- Format: CSV, one line per sample, one sample per second
- Header printed once at startup:

```text
raw_adc,class,prob_normal,prob_warning,prob_danger
```

- Example rows:

```text
1800,Warning,0.0000,0.9839,0.0161
2800,Danger,0.0000,0.0004,0.9996
900,Normal,0.9969,0.0031,0.0000
```

The probabilities are printed with four decimal places. They come from the same
GaussianNB constants used for the LED decision, evaluated by
`gas_model_predict_proba()`.

## Firmware flow

```text
setup()
  Serial.begin(115200)
  configure LED pins as outputs, all off
  analogReadResolution(12)
  analogSetPinAttenuation(34, ADC_11db)
  print header

loop()
  raw = analogRead(34)
  cls = gas_model_predict(raw)
  gas_model_predict_proba(raw, probs)
  setLEDs(cls)
  print CSV row
  delay(1000)
```

`gas_model_predict()` computes the argmax without calling `expf()`.
`gas_model_predict_proba()` performs a numerically stable softmax for logging.

## Building and uploading

1. Install ESP32 board support in the Arduino IDE.
2. Open `firmware/esp32_gas_detection/esp32_gas_detection.ino`.
3. Confirm `gas_model.h` is in the same folder. It is generated by
   `python -m src.export_embedded`; do not edit it by hand.
4. Select a compatible ESP32 board. A generic ESP32 Dev Module configuration is
   a reasonable starting point; adjust flash/partition settings to your board.
5. Upload and open the Serial Monitor at 115200 baud.

The sketch uses the ESP32 Arduino core APIs `analogReadResolution`,
`analogSetPinAttenuation` and `Serial.printf`. The generated C header has been
host-compiled as part of the parity test. The sketch itself has **not** been
compiled with the ESP32 toolchain or run on a device in this repository.

## Safety notes

- The MQ-5 is not a certified leak detector. Its output depends on warm-up,
  supply, humidity, sensor ageing and the target gas.
- Allow the sensor to warm up according to its datasheet before interpreting
  readings. Warm-up readings are not representative.
- Do not power the heater from a GPIO pin. Use a supply that can provide the
  module's required heater current.
- Keep the 3.3 V ADC limit in mind. A divider or level shifter may be required.
- Add an independent fail-safe alarm path for any real installation. Do not rely
  on this classifier, the ESP32 or the LEDs for life-safety decisions.
